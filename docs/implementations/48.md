## Implementation summary

Declared locked Playwright/PNG tooling, a single browser command with two owned
previews, a generic evidence wrapper, and an isolated historical-baseline command.
Routine acceptance uses controlled tile/search responses and rejects unexpected
external requests. Browser synchronization uses observable bounded conditions;
ESLint rejects fixed sleeps except locally justified elapsed-time assertions.
CI invokes contributor commands in separate checks/browser jobs and uploads
artifacts even on failure. Testing references document selection, helpers,
coverage, probes and evidence.

## Decisions and tradeoffs

- The pinned base includes spec #44, which #48 explicitly uses as prior art.
  Its open PR #47 is the dependency: publish against `implement/44-theme-modes`
  and retarget to main after that PR merges.
- The spec already approves public command/browser-rendered test seams.
- Navigation shares a host-aware preview port; the second preview supplies
  direct map acceptance. Both previews are owned, bounded and cleaned up.
- Historical baselines install current locked verification tooling separately
  and retain the original application checkout/lockfile. Metadata identifies
  both revisions and the tooling lock fingerprint.
- Photon/official-raster probes preserve assertions and remain opt-in.
  Production probes are explicitly excluded from routine runs and require
  deployed hosts; fixture rendering proves neither availability nor coverage.
- Three delayed observations remain because elapsed time itself is tested:
  canceled search responses, absent cached-tile retries and canceled navigation.
- An unchanged 2-second suggestion wait failed under concurrent load; a bounded
  10-second observable wait passed. This changes the deadline, not the assertion.

- Round 1 review extracted detached process ownership, termination, output capture
  and flushing into `scripts/process-supervisor.mjs`. Historical runs copy that
  dependency beside the isolated runner. Public command lifecycle tests cover
  successful output flushing and interruption in addition to retained failures.
  This is a review refactor; existing public failure tests passed before extraction.

- The first clean final attempt exposed a torn marker/canvas geometry read
  during the Japanese phone resize case. A shared observable helper now measures
  both rectangles atomically and requires canvas dimensions to fit the current
  map container before checking the original two-pixel centering tolerance.
  The Enter-selection case reuses it; vertical tolerance remains unchanged.
- Interrupted output without canonical final totals now records `testSummary:
null`, rather than inventing zero counts. A public interruption assertion
  failed before this correction and passed afterward.

- A subsequent immutable full attempt completed 57 passed/1 failed/2 skipped.
  Theme keyboard activation could run after reload while the button was still
  disabled during hydration. `waitForThemeReady` now shares bounded enabled-state
  readiness, including after reload before keyboard activation. Existing keyboard
  and pre-paint assertions are preserved; focused theme cycle passed 1/1.

## Approved deviations

None. Application behavior, sources, attribution and theme semantics are unchanged.

## Limitations

POSIX process groups support runner cleanup on Linux/macOS; native Windows is
not currently supported. CI has been inspected locally but has not yet run on
GitHub. No live-provider, deployed-host or nationwide coverage result is claimed.

The first historical full run used inconsistent map/home addresses and failed
its home-link assertion. Its output remains retained; it is not passing baseline
evidence. An initial isolated-helper attempt exposed an incompatible historical
preview option, fixed by using the existing exported preview API. Initial fixture
red evidence was a missing fixture module, not a pre-change provider outage.
